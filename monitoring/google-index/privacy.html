GEO Lab Index Monitor

Privacy policy

How this personal monitoring utility handles Google Search Console data.

Purpose and operator

Helen Bird operates GEO Lab Index Monitor to study the Google index status of GEO Lab's own public research website. The workflow is for the owner's use. These support pages do not provide account registration or a Google sign-in service for visitors.

Data used

The workflow requests URL Inspection observations for a reviewed set of URLs inside the GEO Lab Search Console property. Returned fields can include indexing verdicts, coverage and fetch states, crawl times, canonical URLs, sitemap associations and referring URLs. It also reads the site's Sitemap processing status.

The monitoring workflow uses these observations to retain evidence, compare changes and create private operational alerts. It does not call language models to process the observations.

Google authorization

Routine checks use webmasters.readonly. A separate, locally used webmasters grant supports a one-time Sitemap submission. Google's permissions may cover other properties accessible to the authorizing account; the application enforces a fixed GEO Lab property and reviewed URL allowlist.

OAuth access and refresh tokens are handled by the local authorization program, macOS Keychain and the selected private repository's encrypted GitHub Actions Secret. The local desktop-client configuration is kept in a private, Git-ignored location. Credential values are not committed to the public project.

Processing and storage

Google processes API and authorization requests. GitHub Actions runs the scheduled checks; a separate private GitHub repository stores detailed responses, snapshots, histories and private alert Issues. Raw Search Console data is not deployed to GitHub Pages.

Any public research summary requires a separate review before publication. Operational Google data is not used for advertising or sold. These support pages contain no analytics script or sign-in form; hosting providers may process ordinary request metadata under their own policies.

The use and transfer of information received from Google APIs follows the Google API Services User Data Policy, including its applicable Limited Use requirements.

Retention and control

Private observations are retained as dated research and operational history until the owner removes them. Local write credentials are removed after confirmed Sitemap submission; this local removal does not revoke the Google-side grant.

The owner can review or revoke the application's access in their Google Account's third-party connections settings. Revocation can interrupt monitoring and may affect grants associated with the same Google Cloud project. The owner controls the private repository, stored history, workflow schedule and encrypted repository Secret.

Contact

The maintainer is Helen Bird. General technical questions can be raised through the public project Issues. Do not include credentials or private Google data in a public message. The Google consent screen provides the configured support contact for authorization questions.
