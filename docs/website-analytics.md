# Website analytics

Website analytics and repository traffic are separate. The public research site uses a Google Analytics 4 web data stream for page views and file-link clicks. GitHub's repository Traffic view covers a separate rolling 14-day window.

## Setup

Use the existing web stream for `https://helen-bird.github.io/geo-platform-observation/`. Keep Google signals and advertising personalization off. In Enhanced Measurement, keep page loads and file downloads enabled; leave history-only page changes, scrolls, outbound clicks, site search, forms and videos off. Use GA4's built-in `file_download`, which includes `.xlsx`, and do not add a second download listener. Write only the stream's public ID to `assets/analytics-config.json` as `{"measurement_id":"G-..."}`. Rebuild with `python3 scripts/build_site.py --preserve-evidence` and run `python3 scripts/check_publication.py` before deploying.

The tag is limited to public research reading pages: reports, guides, HTML appendices and evidence readers, including individual HTML responses. Raw data files and archives do not emit page views. An eligible link click can still be measured on the reading page that links to the file. Slice Worksheet events by the exact Guide page and file name, since other readers may have other file links. It loads Google Analytics only after the visitor opts in and respects browser Global Privacy Control and Do Not Track settings. The site explains this on the [analytics privacy page](../privacy.html). It supplies only the page path, recognized campaign parameters and the referring origin to GA4's page-view configuration. Do not put a person's name, account ID or email address in an attribution tag.

Queue consent and the shared settings before the tag's initialization event, then apply those same settings to the stream configuration. This also covers a connected Google tag that initializes before processing the stream-specific configuration. Verify the actual outgoing URL and campaign fields; the presence of a script element or a configuration command alone is not proof that the settings reached an event.

## Links and reporting

For the Lab #07 post, set source to `x`, medium to `social`, campaign to `geo-lab-07`, and content to `original` using the corresponding UTM parameters. Use `reply` or `quote` for the corresponding placement. Preserve the canonical URL. Untagged traffic from `t.co` or `x.com` may still be observable as referral traffic if the browser preserves the source; it cannot reliably be assigned to a post. ChatGPT Search links may carry `utm_source=chatgpt.com`; the referring origin can also provide a signal. Report visits without either signal as direct or unknown.

For GEO Lab #08 distribution, the measurement guide accepts the registered Reddit comment links under `geo_lab_08_distribution`. Use a distinct `utm_content` for each link placement, and register new values in the loader before sharing. Use fixed, lowercase labels without personal data; pick a source, medium, campaign and unique placement ID. Existing X and ChatGPT link handling is unchanged. In GA4, use Session manual ad content for a placement breakdown, and include only the exact production campaign.

Registered directory links use the same campaign and an exact source, medium and placement combination on the measurement guide. Test links append `geo_test=1` and use `geo_lab_08_distribution_qa` in GA4. Keep the canonical URL for directories that require clean links. Those submissions can only be attributed when a referrer is available.

For verification, start in a dedicated tab with `geo_test=1`. Registered Reddit placement links use the separate `geo_lab_08_distribution_qa` campaign and retain their placement. Other checks use `geo-qa / test`, campaign `analytics-setup`. Each QA group has a cookie namespace separate from production. The test context persists in that tab as you follow links to other research pages, even when the next URL is clean. Close the test tab after use. Open any additional test tab with its own QA link rather than assuming it inherits test mode. When browser storage is unavailable, add the test marker on every page. The “Analytics test mode” notice identifies an active test context. Allow analytics when you intend to verify a real event, and separately verify refusal, GPC or Do Not Track without sending events.

In audience reporting, exclude Session campaign `geo_lab_08_distribution_qa` or `analytics-setup`, and exclude `geo-qa / test` if reviewing a source/medium export. Keep labeled test events for acceptance, and annotate any known older diagnostic hit backed by evidence. Prefer report filters for this purpose. Do not activate permanent IP-based filters until the associated traffic rule has been validated. Reconcile Worksheet clicks by campaign and file name, and use Realtime or the processed exploration as a readback. DebugView can be checked if available.

Before sharing, generate and check the production URL, reserving the QA URL for testing. After sharing, reopen the published post or comment and confirm the target after any short-link redirect matches all four UTM fields. Record the post URL, actual target and publish time. Mark a linkless comment as a community interaction. Where a link has clicks but no sessions, report clicks from the platform and sessions from GA4 separately; this static host does not expose an independent arrival count.

`file_download` measures a link click, irrespective of whether the file finishes downloading or is used. Source labels describe observable traffic. User consent and successful tag delivery determine the scope of the measure.
