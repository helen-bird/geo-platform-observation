1. Choose one real buyer question

For a discovery test, use a question someone would ask before learning your product name. Save its exact wording. Define whether you are tracking a person, project, product or distinctive resource. Record a company or author separately if their name alone does not identify the product.

Use one workbook copy for each exact question and target. Compare like-for-like settings. Keep consumer web and API measurements separate, even if the model names look similar.

2. Run and save the baseline

  1. Number the planned slots and set a retry rule before you run. Ten answers can be a manageable pilot. Use more answers across different collection windows when the decision requires better precision.
  2. Start a fresh session each time. Record platform, interface, model label, reasoning level, locale, and personalization. Save the search setting and whether you observed search separately.
  3. In Attempts, record the time, slot and attempt ID, and where the full answer is saved. Preserve failed attempts. Give a retry a new attempt ID and the same slot. Select at most one complete answer per slot.
  4. In Sources, attach each exact URL to its attempt and indicate where it appeared. In Competitors, save each recommended alternative with a consistent name, its position and the exact excerpt. Keep raw conversations private unless they are reviewed for sensitive information.

3. Distinguish what was named, cited and recommended

What counts as a positive observation
MeasureWhen to mark Yes
MentionThe final answer explicitly names the target or a predeclared alias.
RecommendationThe answer actively suggests the target for the buyer’s task. A neutral description, rejection or link alone gets No.
Strict final citationAn identifiable link or inline citation in the final answer points to the target’s own or authored material under your ownership rule.
Observed citation in Lab #09A recorded body link, inline citation card or main source points to the target. Keep the original link role and note incomplete coverage.
More exposureA target URL appears in the separately labelled More list. A captured positive can be scored with partial coverage. Score No only when the complete list is available. Report coverage alongside the rate.

Record No when the needed evidence is available and no qualifying event appears. Record Unknown when coverage is insufficient. A page shown only in More leaves recommendation and citation unchanged. A failed attempt remains in the attempt record and supplies no answer-level score.

Report Yes / (Yes + No), unknowns and failed attempts for each measure. A missing denominator produces no rate. Compare the original Lab #09 observed-citation count alongside panel coverage: absence in the saved links does not establish absence from an uncaptured panel.

4. Record a change and repeat

  1. Freeze the baseline. Save the existing page or resource, published URL, exact question, scoring rule, settings and attempts.
  2. Record the change. Save what shipped, the new version and the actual deployment time. Record outside promotion separately.
  3. Check whether the new version can be found. Verify the live version and that its content is readable. Check for evidence of that version in relevant search results or official index tools. Record what you can verify and mark unknowns. Access by direct link only establishes that the page can be fetched.
  4. Run Retest 1 and Retest 2. Repeat the same question, settings, slot and retry rules. Collect the second retest in a later window, such as one week later. Track platform changes and keep a reference question, resource or set of competitors when possible.

Use Results to compare matching conditions in percentage points. Split results when the interface, effort, search setting, prompt version or scoring rule changes.

Illustrative numbers. If recommendations move from 2/10 to 4/10, report 20% to 40% (+20 percentage points), with both denominators. Repeated batches help assess whether the difference persists. Platform changes and other events can still account for some or all of it.

When the result is unclear

Can I claim improvement if the model or prompt changed?
Report the two results with their conditions and keep the change in your log. Start a new baseline with the current settings before making a like-for-like comparison.
Can I read the rate as zero when the sources are missing?
Score what is visible in the final answer. Mark the missing panel as Unknown. Show the number of known answers next to the numerator and keep the missing answers in the coverage total.
When should I run the first retest?
Check the live URL and the current version first. Look for dated evidence of the new content in your chosen search path. If discoverability remains unknown, record that limit before interpreting the retest.
